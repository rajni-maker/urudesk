# PixelSupport Phase 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Cut v1 down to a two-role helpdesk (Internal Admin + Client) running on a fresh Supabase project.

**Architecture:** Next.js 16 App Router with Server Components and Server Actions, on Supabase (auth + Postgres + RLS). All data access goes through the user's cookie session, so RLS enforces who sees what. The only exception is invites, which use the service-role key. Pages are server-rendered. The new-ticket and invite forms are the only client components, and they exist only for inline errors.

**Tech Stack:** Next.js 16.2 (`proxy.ts`, async `params`/`searchParams`), React 19, Supabase (`@supabase/ssr`, `@supabase/supabase-js`), Tailwind 4, Resend over fetch, a Slack incoming webhook, and `node --test` with native TS type stripping (Node 24).

**Spec:** `docs/superpowers/specs/2026-11-04-phase1-design.md`

## Global Constraints

- Work on branch `phase1`. **Do not commit or push in any task.** The user tests in the app first and approves; committing is the last task.
- Leave v1's production Supabase project alone. All SQL runs against the **new** project, which the user applies by hand in its SQL editor.
- Roles are exactly `'admin' | 'client'`. Statuses are exactly `'open' | 'in_progress' | 'resolved'`. Priorities are exactly `'low' | 'normal' | 'high'`, default `'normal'`.
- `lib/ai.ts` and `@anthropic-ai/sdk` stay in the repo untouched, and Phase 1 code never imports them. `lib/roles.ts` must keep exporting `roleLabel`, `isInternal`, and `draftPerspective`, and `lib/tickets.ts` must keep exporting the `TicketPriority` type, because `lib/ai.ts` imports these and has to keep compiling.
- Notifications are best-effort. They never throw into an action and do nothing when their env var is unset.
- Next.js 16: `params` and `searchParams` are Promises (`await` them), and the middleware file is `proxy.ts` exporting `proxy`. If an API looks unfamiliar, check `node_modules/next/dist/docs/` before using it.
- Every task ends with `npm run build` and `npm run lint` passing. Task 2 adds `npm test`, and from then on it must pass too.

## Deviations from the spec (flagged for the user)

1. **Invite role is set by the server action, not by the trigger.** When Supabase runs `inviteUserByEmail`, it inserts the user *before* it sets `invited_at`. A trigger that checks `invited_at` would therefore see null and make every invitee a client. So the trigger always inserts `'client'`, and `inviteMember` then promotes the new profile with the service-role client. The result is just as safe: the public signup path can never set a role.
2. **Clients can read admin profiles (`role = 'admin'` rows).** Without this, a client can't see who replied or who their ticket is assigned to. Admin names and emails become visible to clients.
3. **Assign events store display names** in `from_value`/`to_value`, not profile ids, so the event log needs no extra lookups.
4. **New route `app/auth/confirm/route.ts`** handles invite links (`token_hash` flow). The user also changes the "Invite user" email template once in the Supabase dashboard (Task 1).

```sql
-- PixelSupport Phase 1 — whole schema. Apply once, by hand, in the NEW project's SQL editor.

-- ---------- Tables ----------------------------------------------------------

create table public.profiles (
  id         uuid primary key references auth.users (id) on delete cascade,
  email      text not null,
  full_name  text not null default '',
  role       text not null default 'client' check (role in ('admin', 'client')),
  created_at timestamptz not null default now()
);

create table public.tickets (
  id          uuid primary key default gen_random_uuid(),
  number      serial unique,
  subject     text not null check (length(trim(subject)) > 0),
  body        text not null,
  status      text not null default 'open' check (status in ('open', 'in_progress', 'resolved')),
  priority    text not null default 'normal' check (priority in ('low', 'normal', 'high')),
  client_id   uuid not null references public.profiles (id),
  assignee_id uuid references public.profiles (id),
  created_at  timestamptz not null default now(),
  updated_at  timestamptz not null default now()
);
create index tickets_client_id_idx on public.tickets (client_id);
create index tickets_status_idx on public.tickets (status);

create table public.ticket_replies (
  id         uuid primary key default gen_random_uuid(),
  ticket_id  uuid not null references public.tickets (id) on delete cascade,
  author_id  uuid not null references public.profiles (id),
  body       text not null check (length(trim(body)) > 0),
  created_at timestamptz not null default now()
);
create index ticket_replies_ticket_id_idx on public.ticket_replies (ticket_id);

create table public.ticket_events (
  id         uuid primary key default gen_random_uuid(),
  ticket_id  uuid not null references public.tickets (id) on delete cascade,
  actor_id   uuid not null references public.profiles (id),
  kind       text not null check (kind in ('status', 'assign')),
  from_value text,
  to_value   text,
  created_at timestamptz not null default now()
);
create index ticket_events_ticket_id_idx on public.ticket_events (ticket_id);

-- ---------- Functions + triggers -------------------------------------------

create function public.is_admin() returns boolean
language sql stable security definer set search_path = public as $$
  select coalesce((select role = 'admin' from public.profiles where id = auth.uid()), false);
$$;

-- Every new auth user gets a client profile. Admins are made by the invite
-- server action (service role) or by hand in SQL — never by signup metadata.
create function public.handle_new_user() returns trigger
language plpgsql security definer set search_path = public as $$
begin
  insert into public.profiles (id, email, full_name)
  values (new.id, new.email, coalesce(new.raw_user_meta_data ->> 'full_name', ''));
  return new;
end;
$$;

create trigger on_auth_user_created
  after insert on auth.users
  for each row execute function public.handle_new_user();

create function public.touch_updated_at() returns trigger
language plpgsql as $$
begin
  new.updated_at = now();
  return new;
end;
$$;

create trigger tickets_touch_updated_at
  before update on public.tickets
  for each row execute function public.touch_updated_at();

-- ---------- Grants ----------------------------------------------------------

revoke all on public.profiles, public.tickets, public.ticket_replies, public.ticket_events from anon, authenticated;

grant select on public.profiles to authenticated;
grant update (full_name) on public.profiles to authenticated;  -- role is never client-writable
grant select, insert, update, delete on public.tickets to authenticated;
grant select, insert on public.ticket_replies, public.ticket_events to authenticated;
grant usage, select on sequence public.tickets_number_seq to authenticated;

-- ---------- RLS -------------------------------------------------------------

alter table public.profiles       enable row level security;
alter table public.tickets        enable row level security;
alter table public.ticket_replies enable row level security;
alter table public.ticket_events  enable row level security;

-- profiles: own row, every admin row (so clients see who replied), admins see all.
create policy profiles_select on public.profiles for select to authenticated
  using (id = auth.uid() or role = 'admin' or public.is_admin());
create policy profiles_update on public.profiles for update to authenticated
  using (id = auth.uid() or public.is_admin())
  with check (id = auth.uid() or public.is_admin());

-- tickets: clients read/insert their own (open, unassigned); admins do everything.
create policy tickets_select on public.tickets for select to authenticated
  using (client_id = auth.uid() or public.is_admin());
create policy tickets_insert on public.tickets for insert to authenticated
  with check (
    public.is_admin()
    or (client_id = auth.uid() and status = 'open' and assignee_id is null)
  );
create policy tickets_update on public.tickets for update to authenticated
  using (public.is_admin()) with check (public.is_admin());
create policy tickets_delete on public.tickets for delete to authenticated
  using (public.is_admin());

-- replies: anyone who can see the ticket can read and post, as themselves.
create policy replies_select on public.ticket_replies for select to authenticated
  using (
    public.is_admin()
    or exists (select 1 from public.tickets t where t.id = ticket_id and t.client_id = auth.uid())
  );
create policy replies_insert on public.ticket_replies for insert to authenticated
  with check (
    author_id = auth.uid()
    and (
      public.is_admin()
      or exists (select 1 from public.tickets t where t.id = ticket_id and t.client_id = auth.uid())
    )
  );

-- events: clients read their tickets' log; only admins write it.
create policy events_select on public.ticket_events for select to authenticated
  using (
    public.is_admin()
    or exists (select 1 from public.tickets t where t.id = ticket_id and t.client_id = auth.uid())
  );
create policy events_insert on public.ticket_events for insert to authenticated
  with check (actor_id = auth.uid() and public.is_admin());
```

```ts
// Ticket vocabulary for Phase 1: three statuses, three priorities.
// Deliberately import-free so `node --test` can load it directly.

export type TicketStatus = "open" | "in_progress" | "resolved";
export type TicketPriority = "low" | "normal" | "high";

export const STATUS_OPTIONS: TicketStatus[] = ["open", "in_progress", "resolved"];
export const PRIORITY_OPTIONS: TicketPriority[] = ["low", "normal", "high"];

export const STATUS_LABELS: Record<TicketStatus, string> = {
  open: "Open",
  in_progress: "In Progress",
  resolved: "Resolved",
};

export const PRIORITY_LABELS: Record<TicketPriority, string> = {
  low: "Low",
  normal: "Normal",
  high: "High",
};

export const DARK_STATUS_STYLES: Record<TicketStatus, string> = {
  open: "bg-[#6366f1]/[0.12] text-[#818cf8]",
  in_progress: "bg-[#f59e0b]/[0.12] text-[#fbbf24]",
  resolved: "bg-[#22c55e]/[0.12] text-[#4ade80]",
};

export const DARK_PRIORITY_STYLES: Record<TicketPriority, string> = {
  low: "bg-white/[0.06] text-[#a0a0b8]",
  normal: "bg-[#06b6d4]/[0.12] text-[#22d3ee]",
  high: "bg-[#ef4444]/[0.12] text-[#f87171]",
};

export function isStatus(v: unknown): v is TicketStatus {
  return typeof v === "string" && (STATUS_OPTIONS as string[]).includes(v);
}

export function isPriority(v: unknown): v is TicketPriority {
  return typeof v === "string" && (PRIORITY_OPTIONS as string[]).includes(v);
}

/**
 * Status a ticket moves to when assigned, or null to leave it. Assigning an
 * open ticket means work is starting; anything else keeps its status, and
 * unassigning never moves it.
 */
export function autoStatusOnAssign(
  current: TicketStatus,
  assigneeId: string | null,
): TicketStatus | null {
  if (!assigneeId) return null;
  return current === "open" ? "in_progress" : null;
}

type Param = string | string[] | undefined;

/** Reads `?status=&priority=` from the ticket list URL; invalid values become null. */
export function parseFilters(sp: { status?: Param; priority?: Param }): {
  status: TicketStatus | null;
  priority: TicketPriority | null;
} {
  const first = (v: Param) => (Array.isArray(v) ? v[0] : v);
  const status = first(sp.status);
  const priority = first(sp.priority);
  return {
    status: isStatus(status) ? status : null,
    priority: isPriority(priority) ? priority : null,
  };
}

export function formatDateTime(iso: string): string {
  return new Date(iso).toLocaleString("en-IN", {
    dateStyle: "medium",
    timeStyle: "short",
    timeZone: "Asia/Kolkata",
  });
}
```

```ts
import { redirect } from "next/navigation";
import { createClient } from "@/lib/supabase/server";
import type { UserRole } from "@/lib/roles";

export type Profile = { id: string; email: string; full_name: string; role: UserRole };

// Every signed-in page and action starts here. Returns the RLS-bound client
// and the caller's profile, or redirects to /login.
export async function requireProfile() {
  const supabase = await createClient();
  const {
    data: { user },
  } = await supabase.auth.getUser();
  if (!user) redirect("/login");

  const { data: profile } = await supabase
    .from("profiles")
    .select("id, email, full_name, role")
    .eq("id", user.id)
    .single();
  if (!profile) redirect("/login");

  return { supabase, profile: profile as Profile };
}

// Same, but only for admins. Pages check this themselves rather than trusting
// proxy.ts alone.
export async function requireAdmin() {
  const session = await requireProfile();
  if (session.profile.role !== "admin") redirect("/tickets");
  return session;
}

export function displayName(
```

```tsx
import { redirect } from "next/navigation";
```

```ts
  autoStatusOnAssign,
  isPriority,

  PRIORITY_LABELS,
  type TicketStatus,
} from "@/lib/tickets";
import { slackNewTicket, slackTicketAssigned } from "@/lib/slack";
import { notifyNewTicket, notifyNewReply, notifyStatusChange } from "@/lib/email";

export type TicketFormState = { error: string } | null;

export async function createTicket(
  _prev: TicketFormState,
  formData: FormData,
): Promise<TicketFormState> {
  const { supabase, profile } = await requireProfile();
  const subject = String(formData.get("subject") ?? "").trim();
  const body = String(formData.get("body") ?? "").trim();
  const priority = String(formData.get("priority") ?? "normal");

  if (!subject || !body) return { error: "Subject and description are required." };
  if (!isPriority(priority)) return { error: "Pick a valid priority." };

  // Admins raise tickets on a client's behalf; clients always raise their own.
  const clientId =
    profile.role === "admin" ? String(formData.get("clientId") ?? "") : profile.id;
  if (!clientId) return { error: "Pick the client this ticket is for." };

  const { data: ticket, error } = await supabase
    .from("tickets")
    .insert({ subject, body, priority, client_id: clientId })
    .select("id")
    .single();
  if (error || !ticket) return { error: error?.message ?? "Could not create the ticket." };

  // Admin profiles are readable by every signed-in user (RLS), so this works for clients too.
  const { data: admins } = await supabase.from("profiles").select("email").eq("role", "admin");
  await Promise.all([
    slackNewTicket({
      ticketId: ticket.id,
      subject,
      priority: PRIORITY_LABELS[priority],
      createdBy: displayName(profile),
    }),
    notifyNewTicket({
      to: (admins ?? []).map((a) => a.email).filter(Boolean),
      ticketId: ticket.id,
      subject,
    }),
  ]);

  revalidatePath("/tickets");
  redirect(`/tickets/${ticket.id}`);
}
```

```ts
type TicketForUpdate = {
  id: string;
  subject: string;
  status: TicketStatus;
  assignee_id: string | null;
  client: { email: string } | null;
  assignee: { full_name: string; email: string } | null;
};

async function loadTicket(
  supabase: Awaited<ReturnType<typeof requireProfile>>["supabase"],
  ticketId: string,
): Promise<TicketForUpdate> {
  const { data, error } = await supabase
    .from("tickets")
    .select(
      "id, subject, status, assignee_id, client:profiles!tickets_client_id_fkey(email), assignee:profiles!tickets_assignee_id_fkey(full_name, email)",
    )
    .eq("id", ticketId)
    .single();
  if (error || !data) throw new Error(error?.message ?? "Ticket not found.");
  return data as unknown as TicketForUpdate;
}

function emailClientStatus(t: TicketForUpdate, status: TicketStatus) {
  return notifyStatusChange({
    to: t.client?.email ? [t.client.email] : [],
    ticketId: t.id,
    subject: t.subject,
    statusLabel: STATUS_LABELS[status],
  });
}

export async function addReply(ticketId: string, formData: FormData) {
  const { supabase, profile } = await requireProfile();
  const body = String(formData.get("body") ?? "").trim();
  if (!body) return;

  const { error } = await supabase
    .from("ticket_replies")
    .insert({ ticket_id: ticketId, author_id: profile.id, body });
  if (error) throw new Error(error.message);

  // Only admin replies notify (the client, by email).
  if (profile.role === "admin") {
    const t = await loadTicket(supabase, ticketId);
    await notifyNewReply({
      to: t.client?.email ? [t.client.email] : [],
      ticketId,
      subject: t.subject,
      fromLabel: displayName(profile),
    });
  }
  revalidatePath(`/tickets/${ticketId}`);
}

export async function changeStatus(ticketId: string, formData: FormData) {
  const { supabase, profile } = await requireAdmin();
  const status = formData.get("status");
  if (!isStatus(status)) return;

  const t = await loadTicket(supabase, ticketId);
  if (t.status === status) return;

  const { error } = await supabase.from("tickets").update({ status }).eq("id", ticketId);
  if (error) throw new Error(error.message);
  await supabase.from("ticket_events").insert({
    ticket_id: ticketId,
    actor_id: profile.id,
    kind: "status",
    from_value: t.status,
    to_value: status,
  });
  await emailClientStatus(t, status);
  revalidatePath(`/tickets/${ticketId}`);
  revalidatePath("/tickets");
}

export async function changePriority(ticketId: string, formData: FormData) {
  const { supabase } = await requireAdmin();
  const priority = formData.get("priority");
  if (!isPriority(priority)) return;

  const { error } = await supabase.from("tickets").update({ priority }).eq("id", ticketId);
  if (error) throw new Error(error.message);
  revalidatePath(`/tickets/${ticketId}`);
  revalidatePath("/tickets");
}

export async function assignTicket(ticketId: string, formData: FormData) {
  const { supabase, profile } = await requireAdmin();
  const assigneeId = String(formData.get("assigneeId") ?? "") || null;

  const t = await loadTicket(supabase, ticketId);
  if (t.assignee_id === assigneeId) return;
  let assigneeName = "Unassigned";
  if (assigneeId) {
    const { data: a } = await supabase
      .from("profiles")
      .select("full_name, email, role")
      .eq("id", assigneeId)
      .single();
    if (!a || a.role !== "admin") throw new Error("Tickets can only be assigned to admins.");
    assigneeName = displayName(a);
  }
  const fromName = t.assignee ? displayName(t.assignee) : "Unassigned";

  const nextStatus = autoStatusOnAssign(t.status, assigneeId);
  const { error } = await supabase
    .from("tickets")
    .update({ assignee_id: assigneeId, ...(nextStatus ? { status: nextStatus } : {}) })
    .eq("id", ticketId);
  if (error) throw new Error(error.message);

  await supabase.from("ticket_events").insert([
    { ticket_id: ticketId, actor_id: profile.id, kind: "assign", from_value: fromName, to_value: assigneeName },
    ...(nextStatus
      ? [{ ticket_id: ticketId, actor_id: profile.id, kind: "status", from_value: t.status, to_value: nextStatus }]
      : []),
  ]);

  if (assigneeId) {
    await slackTicketAssigned({
      ticketId,
      subject: t.subject,
      assigneeName,
      assignedByName: displayName(profile),
    });
  }
  if (nextStatus) await emailClientStatus(t, nextStatus);

  revalidatePath(`/tickets/${ticketId}`);
  revalidatePath("/tickets");
}
```

```tsx
  );
}
```

```ts
"use server";

import { revalidatePath } from "next/cache";
import { createAdmin } from "@/lib/supabase/admin";
import { requireAdmin } from "@/lib/session";
import { isUserRole, roleLabel } from "@/lib/roles";

export type InviteState = { error: string } | { success: string } | null;

// Admin-only. Supabase emails the invite; the trigger creates a 'client'
// profile, and we promote it here when inviting an admin (see plan deviation 1).
export async function inviteMember(_prev: InviteState, formData: FormData): Promise<InviteState> {
  await requireAdmin();
  const email = String(formData.get("email") ?? "").trim().toLowerCase();
  const role = formData.get("role");
  if (!email) return { error: "Email is required." };
  if (!isUserRole(role)) return { error: "Pick a role." };

  const admin = createAdmin();
  // The invite link itself comes from the dashboard email template (Task 1),
  // which points at /auth/confirm → /reset-password.
  const { data, error } = await admin.auth.admin.inviteUserByEmail(email, { data: { role } });
  if (error || !data.user) return { error: error?.message ?? "Invite failed." };

  if (role === "admin") {
    const { error: roleError } = await admin.from("profiles").update({ role }).eq("id", data.user.id);
    if (roleError) return { error: `Invited, but couldn't set the role: ${roleError.message}` };
  }

  revalidatePath("/team");
  return { success: `Invite sent to ${email} as ${roleLabel(role)}.` };
}
```
